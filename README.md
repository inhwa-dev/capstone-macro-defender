# 캡스톤 프로젝트

## MORPH 회의용 준비안

MORPH는 팀이 관리하는 모의 웹페이지에서 조회 업무를 실행하는 적응형 매크로다. 화면이 바뀌어 기존 방식이 실패하면 대체 방법을 찾아 실행한다. 결과를 확인한 뒤 성공한 방법을 저장하고, 같은 변경을 만나면 재사용한다.

이 문서의 모프 방향, 담당자, 첫 시연 범위는 회의에서 확정한다. 예시 업무는 모의 페이지에서 `CS101` 강좌를 조회하는 것이다.

## 작업 위치

| 역할 | 위치 | 담당 기능 |
| --- | --- | --- |
| A 실행 엔진 | [backend/runner](backend/runner) | 정상 조회 실행, 실패 단계 기록, 대체 후보 실행, 전체 실행 흐름 연결 |
| B 모의 환경·테스트 | [frontend/mock-site](frontend/mock-site), [tests](tests) | 정상·변경 페이지, 기대 결과, 실패 원인 분류와 통합 테스트 |
| C 적응·복구 | [ai/recovery](ai/recovery) | 저장된 복구 방법 확인, 대체 후보 선정 |
| D 검증·경험 저장 | [backend/experience](backend/experience) | 조회 결과 검증, 성공한 방법 저장 및 조회 |
| E 사용 화면·시연 | [frontend](frontend) | 모프 시작·중지 화면, 진행 상태와 복구 이력, 시연 순서 |

## 개발 시작 순서

1. 회의에서 대표 조회 업무, 기대 결과, 역할별 담당자를 결정한다.
2. [첫 작업 목록](docs/kickoff.md)의 초안을 확정하고, 역할별로 Issue를 하나씩 등록한다.
3. [연동 예시](docs/handoff.md)로 입력과 출력 형식을 맞춘다. Issue마다 작업 브랜치를 만들고 PR에 완료 기준과 확인 결과를 적는다.
4. 첫 통합에서는 E의 화면에서 시작해 A가 B의 정상 페이지를 조회하는 흐름을 확인한다. 그다음 화면 변경, 복구, 검증, 저장, 재사용을 연결한다.
