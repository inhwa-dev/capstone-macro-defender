# 모듈 연동 예시

모의 조회 업무를 기준으로 한 초안이다. 첫 회의에서 필드 이름과 호출 방식을 조정한다.

| 전달 | 데이터 |
| --- | --- |
| E → A | 작업 ID, 강좌 코드, 시작 요청. 중지할 때는 실행 ID도 전달한다. |
| A → B | 실행 ID, 실패 단계, 관찰된 화면 정보 |
| B → C | 실패 원인, 실패 단계, 확인된 화면 정보. 화면 변경 사례는 C가 검토한다. |
| C ↔ D | 작업 ID, 실패 단계, 화면 변경 정보를 기준으로 저장한 방법을 조회한다. |
| C → A | 대체 요소 ID 또는 후보 없음 |
| A → D | 실행 ID, 요청한 강좌 코드, 실제 조회 결과 |
| A → E | 실행 ID, 상태, 검증된 결과, 복구 여부. D의 복구 이력과 연결할 때도 같은 실행 ID를 쓴다. |

## 시작 요청 예시

```json
{
  "task_id": "course_lookup",
  "course_code": "CS101"
}
```

## 조회 완료 예시

```json
{
  "run_id": "demo-001",
  "status": "completed",
  "course": {
    "code": "CS101",
    "name": "컴퓨터 개론"
  },
  "recovery": "none"
}
```

`recovery`는 정상 실행(`none`), 신규 복구(`new`), 저장한 방법 재사용(`reused`)을 구분한다. 실패나 사용자 확인이 필요한 경우에는 상태와 원인만 표시한다. 조회 결과가 기대와 일치한 복구 방법을 저장하고, 재사용할 때도 결과를 검증한다.
