# 회의에서 확정할 첫 작업

대표 예시는 `CS101` 강좌 조회다. 실제 작업 번호, 담당자, 공유일은 회의에서 정한다.

| 역할 | 첫 Issue 제목 초안 | 완료 기준 | 먼저 공유할 것 |
| --- | --- | --- | --- |
| A | 정상 화면 강좌 조회 및 실행 로그 | 모의 페이지에서 `CS101`을 조회하고 실행 ID와 결과를 기록한다. | E에 시작 요청 형식, B에 실패 로그 예시 |
| B | 정상·변경 모의 페이지와 기대 결과 준비 | 같은 강좌 데이터로 정상 화면과 버튼 이름이 바뀐 화면을 재현할 수 있다. | A·C에 두 화면, D에 강좌별 기대 결과 |
| C | 버튼이 바뀐 화면에서 대체 후보 선정 | 변경 화면의 후보 중 `강좌 검색`에 해당하는 요소 ID를 A에 전달한다. 후보가 없으면 그 상태를 돌려준다. | A에 후보와 후보 없음 응답 예시 |
| D | 조회 결과 검증 | 요청한 강좌와 일치하는 결과, 다른 강좌 결과, 결과 없음에 대해 판정이 나온다. | A에 검증 결과 형식, C에 저장 방법 조회 형식 초안 |
| E | 모프 시작 화면과 결과 표시 | 테스트 값과 시작 요청을 보내고 예시 응답으로 진행 상태와 조회 결과를 표시한다. | A와 시작 요청 및 결과 응답 확인 |

## 회의에서 기록할 내용

- A~E의 실명 담당자와 첫 작업 공유일
- 첫 조회 업무, 테스트 입력, 기대 결과와 변경 화면
- 첫 통합 날짜와 검토할 PR

첫 통합이 끝나면 B가 버튼 위치·구조 변경 사례를 추가하고, A·C·D가 복구 결과를 검증하고 저장하는 흐름을 연결한다. E는 실행 결과와 저장한 방법의 재사용 여부를 화면에 표시한다.
